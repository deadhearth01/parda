# parda v0.1 — design spec

*Date: 2026-10-11 · Status: approved for implementation (owner delegated remaining decisions) · Research basis: `reports/Local PII redaction for AI chats.md`*

**parda** (Hindi/Urdu: "curtain, veil") is an open-source, local-only, real-time PII filter that sits between a user and cloud LLMs / AI agents. It replaces personal data with realistic surrogates before text leaves the machine and restores the real values in the answers.

---

## 1. Intent

| | |
|---|---|
| **Outcome** | Install with one command; point an AI agent (Claude Code, Codex, SDKs) at parda, or press a hotkey to paste into any chat app; names, contacts, IDs and secrets never leave the machine, and answers come back with real values restored. |
| **Users (v0.1)** | (a) developers using AI coding agents / SDKs; (b) everyday chat users of ChatGPT/Claude web or desktop apps (via clipboard). |
| **Constraints** | Local only, no telemetry. Rust. Windows / macOS / Linux. One-command install. Managed via TUI. Near-zero added latency. Permissive license (Apache-2.0 OR MIT). India-first identifiers (Aadhaar, PAN, UPI, GSTIN…) plus global ones. |
| **Success criteria** | (1) Golden corpus: 100% recall on structured identifiers with checksums; ≥ 0.85 recall on person names (incl. Indian names) with the chosen ML model. (2) Added p95 latency on the proxy send path ≤ 10 ms for previously-seen text and ≤ ML budget (default 250 ms, target ≤ 50 ms) for new text. (3) Round-trip: `restore(redact(x)) == x` for all golden texts. (4) Streaming responses restored correctly regardless of chunk boundaries. (5) Builds and tests pass on macOS; CI config for all three OSes. |

**Owner said:** open source, local, real-time, text+image+docs, near-zero latency, cross-platform, one-command install, TUI, better than existing tools, Rust, v0.1 serves agents *and* chat users, include ML name detection, name "parda", architecture = daemon + thin clients, build on the SSD.
**Assumed (documented decisions):** everything else in this spec.

## 2. Scope

### In v0.1
- **Platforms:** macOS (arm64, x86_64), Windows x86_64, Linux x86_64/arm64 (X11; Wayland via data-control protocol; hotkey on Wayland via DE shortcut → `parda paste-safe`).
- **Text detection tiers:** T0 user dictionaries + person blocks; T1 rule packs with validators; T2 one ONNX ML model; merge + policy.
- **Replacement:** realistic surrogates (default) or typed tokens; deterministic per scope; encrypted vault with TTL.
- **Agent proxy:** Anthropic Messages (`/v1/messages`, `/v1/messages/count_tokens`), OpenAI Chat Completions (`/v1/chat/completions`) and Responses (`/v1/responses`); streaming SSE; restore in text and tool-call arguments; redact system prompts and tool results; pass-through auth.
- **Clipboard:** scan-on-copy (text), paste-safe hotkey, restore-on-copy.
- **CLI:** `parda redact|restore|scan|paste-safe|setup|doctor|service|daemon|tui|vault (stats|wipe|reset)|rules|model (list|pull|use)`.
- **Daemon** with local IPC; autostart service install.
- **TUI** (ratatui).
- **Packaging:** `dist` config (shell + PowerShell installers, Homebrew formula, MSI), GitHub Actions CI matrix. (Publishing releases is done by the owner.)
- **Bench:** eval harness (recall / zero-leak / round-trip) + latency harness; golden corpus in repo.

### Out of v0.1 (later sub-projects, each with own spec)
Image pipeline · document pipeline · browser extension · MITM/HTTPS_PROXY mode · accessibility composer guard · Gemini & other providers · GUI · own distilled models.

### v0.1 behaviour for images/documents in proxy traffic
Passed through unchanged; an `UnscannedContent` event is emitted (visible in TUI). Policy `unscanned_media = "allow" | "block"` (default `allow`).

## 3. Architecture

Single binary `parda`; one background **daemon** owns the engine, ML model, vault, cache, proxy listener and clipboard watcher. CLI and TUI are thin clients over a local IPC socket (Unix domain socket on macOS/Linux, named pipe on Windows). No HTTP control API.

```
 clients:  parda tui ──┐   parda redact/scan/… ──┐   parda paste-safe ──┐
                       ▼                          ▼                      ▼
             ┌────────────────────── IPC (parda-ipc) ─────────────────────────┐
             │                       parda daemon                             │
 agents ───► │  proxy (parda-proxy) ─┐                                        │
 (HTTP)      │  clipboard (parda-clip)┼─► Engine (detect+ml+vault+restore) ──► │──► api.anthropic.com
 OS clip ◄──►│                       ┘    events ─► broadcast ─► TUI/logs     │    api.openai.com
             └────────────────────────────────────────────────────────────────┘
```

## 4. Detection

### 4.1 Types
```rust
enum EntityKind { Person, Email, Phone, Address, Url, IpAddress, MacAddress,
  CreditCard, Iban, BankAccount, Ifsc, Aadhaar, Pan, Gstin, Upi, VoterId,
  DrivingLicence, IndianVehicleReg, Passport, UsSsn, UkNino, DateOfBirth,
  Secret, Organization, Custom(String) }
struct Span { start: usize, end: usize }            // byte offsets into UTF-8 input
struct Detection { span: Span, kind: EntityKind, score: f32, source: Source /*Dict|Rule|Ml*/ }
```

### 4.2 Tiers
- **T0 Dictionary** — user entries from `rules.toml`: literal terms and **person blocks** (`name`, optional `aliases`, `emails`, `handles`). Person blocks auto-expand to variants: full name, first, last (if ≥ 3 chars and not a common word), `first.last`, `first_last`, `firstlast`, `f.last`, initials+last, case-insensitive. Aho-Corasick, leftmost-longest. Score 1.0.
- **T1 Rules** — compiled once; each recognizer = regex + optional validator + optional context words (boost) + base score. Packs: `global` (email, phone E.164 + common national formats, IPv4/IPv6, MAC, URL with credentials/query PII, IBAN, credit card), `india` (Aadhaar 12-digit Verhoeff with first digit 2–9 incl. spaced `XXXX XXXX XXXX`; PAN `[A-Z]{3}[ABCFGHLJPT][A-Z]\d{4}[A-Z]`; GSTIN 15-char with checksum; UPI `[\w.-]{2,}@(known handles|[a-z]{2,})`; Voter ID `[A-Z]{3}\d{7}`; DL; vehicle reg; IFSC `[A-Z]{4}0[A-Z0-9]{6}`; Indian mobile `(\+91[\s-]?)?[6-9]\d{9}`), `us_uk` (SSN, NINO), `secrets` (AWS `AKIA…`, GitHub `gh[pousr]_…`, OpenAI `sk-…`, Anthropic `sk-ant-…`, Slack `xox[abpr]-…`, Google `AIza…`, JWT, PEM private key blocks, `password|secret|token|api_key\s*[:=]\s*\S+` context, high-entropy ≥ 4.0 bits/char tokens ≥ 24 chars with key-like context). Dates are **off by default** (false-positive heavy); `DateOfBirth` only with DOB context words.
- **T2 ML** — `OnnxDetector` over a token-classification model. Text is fragmented on paragraph/line boundaries into ≤ `max_tokens` (default 256) windows with 32-token overlap; fragments batched. Labels mapped to `EntityKind` via a per-model label map. Offsets: tokenizer offsets mapped to byte offsets; leading/trailing whitespace trimmed (BPE leading-space issue). Threshold per kind (default 0.5).
- **Model selection gate (first implementation task):** candidates evaluated on the golden corpus (+ optional external samples) on the dev Mac: recall on Person/Address, precision, p50/p95 latency per 256-token fragment on CPU and with CoreML EP. Candidates: (a) GLiNER-PII family ONNX (knowledgator edge/small; label-conditioned), (b) GLiNER2-PII ONNX export, (c) a standard BERT/DeBERTa-style PII token classifier with permissive license, (d) OpenAI Privacy Filter ONNX if size/latency acceptable. Acceptance: permissive license, Person recall ≥ 0.85 on golden, p95 ≤ 250 ms (target ≤ 50 ms). Winner becomes `default` in the model catalog; others remain selectable. If a label-conditioned (GLiNER) model wins, `OnnxDetector` gets a second implementation behind the same trait.

### 4.3 Merge & policy
- Overlaps: prefer higher-tier certainty (Dict > Rule-with-validator > ML > Rule-without-validator), then longer span, then higher score.
- Allow-list (`rules.toml [allow]`): exact terms never redacted (e.g., own product names, public figures).
- Per-kind action from config: `redact` (default), `block` (request refused with explanation), `warn` (log only), `ignore`.

### 4.4 Engine pipeline & latency
```
redact(text, ctx):
  fragments = split(text)                      # paragraphs/lines
  for f in fragments: key = blake3(f)
      cached? -> detections                    # content-hash LRU (default 50k entries, in-memory)
      else    -> T0 + T1 (sync, µs)  ∥  T2 (batched; budget ml_timeout_ms)
  merge -> policy -> replacements via vault (scope)
```
- **Mode** `strict` (default): wait for ML up to `ml_timeout_ms` (250); on timeout/error → request is refused (proxy 503 `parda_ml_unavailable`) — privacy over availability. Mode `fast`: on timeout proceed with T0+T1 and emit `MlSkipped` event.
- Agents resend history every turn ⇒ only new fragments cost ML time.
- Model loaded once at daemon start (warm-up inference on load).

## 5. Replacement, vault, restore

### 5.1 Styles
- `surrogate` (default): realistic same-kind fakes.
- `token`: `⟦PERSON_1⟧`-style typed tokens (numbered per scope).

### 5.2 Surrogate generator (deterministic)
Seed = HMAC-SHA256(vault_key, scope ‖ kind ‖ normalized(real)) → ChaCha RNG. Collision with an existing surrogate or with the real value → re-seed with counter.
- **Person:** keep token count and initial/abbreviation pattern; locale heuristic: if any token ∈ bundled Indian name list → Indian replacement list, else Western list; case pattern preserved per token (`JOHN`→`ARJUN`, `john`→`arjun`). Each name token also registered as its own sub-mapping (first/last) so partial mentions restore.
- **Email:** local part → surrogate (derived from person surrogate if the email belongs to a person block, else random word combo); domain kept if public webmail (gmail.com, yahoo.*, outlook.com, hotmail.com, icloud.com, proton.me, rediffmail.com …) else mapped to `<word>-<word>.example`.
- **Phone:** keep country code, length, grouping, separators; Indian mobiles keep leading digit class [6-9]; random remaining digits.
- **Credit card:** keep length and first digit; random middle; Luhn-valid.
- **Aadhaar:** 12 digits, first 2–9, Verhoeff-valid; keep spacing. **PAN:** keep 4th char (holder type), random rest per pattern. **GSTIN:** keep state code; surrogate PAN inside; valid checksum. **UPI:** surrogate local part, keep handle. **IFSC / Voter / DL / vehicle reg:** pattern-valid randoms keeping state/bank prefix letters.
- **IP:** v4 private→private range, public→random public with same first octet; v6 keep prefix length class.
- **Secret:** keep recognizable prefix (`sk-ant-`, `ghp_`, `AKIA`) + random same-length body.
- **Address / Organization / other ML kinds:** token-style placeholder `⟦ADDRESS_3⟧` in v0.1 (realistic address synthesis deferred).

### 5.3 Vault
- SQLite (`rusqlite`, bundled) at `<data_dir>/vault.db`, WAL mode.
- Table `mappings(scope, kind, real_hmac BLOB, real_ct BLOB, nonce BLOB, surrogate TEXT, created_at, last_used_at)`; unique `(scope, real_hmac)` and `(scope, surrogate)`.
- Real values encrypted (XChaCha20-Poly1305) with the 256-bit vault key; HMAC key derived from vault key (HKDF).
- Key storage: OS keyring (`keyring` crate: macOS Keychain, Windows Credential Manager, Linux Secret Service); fallback `<data_dir>/vault.key` (0600) when keyring unavailable (headless Linux); `parda doctor` reports which.
- In-memory reverse index (surrogate → real) per scope, rebuilt on start, updated on insert.
- TTL: `vault.ttl_days` (default 30) — pruned on start and hourly. `parda vault wipe [--scope]`.
- Scopes: `global` (default). Proxy honours request header `x-parda-scope: <name>`; clipboard uses `clipboard.scope` (default `global`, so the same person gets the same surrogate everywhere).

### 5.4 Restore
- `restore(text, scope)`: Aho-Corasick (leftmost-longest) over all surrogate strings of the scope (+ case variants: lower, UPPER, Title) → real values with case pattern re-applied.
- `StreamRestorer`: feed chunks, emits restored output while holding back only the longest suffix that is a prefix of any surrogate (bounded by max surrogate length − 1); `finish()` flushes. Property-tested: for any chunking, concat(outputs) == restore(concat(inputs)).

## 6. Agent proxy

- Listen `127.0.0.1:8787` (config `proxy.listen`; loopback only unless `proxy.allow_non_loopback=true`).
- Routing by path: `/v1/messages*` → Anthropic upstream (`https://api.anthropic.com`); `/v1/chat/completions`, `/v1/responses` → OpenAI upstream (`https://api.openai.com`); any other path → pass-through to upstream chosen by header heuristics (`anthropic-version` or `x-api-key` → Anthropic, else OpenAI), body untouched. Upstream URLs configurable (supports OpenAI-compatible providers, Ollama, OpenRouter).
- Client setup: `ANTHROPIC_BASE_URL=http://127.0.0.1:8787` ; `OPENAI_BASE_URL=http://127.0.0.1:8787/v1`. `parda setup` prints/writes these (Claude Code: `~/.claude/settings.json` `env` block — only with user confirmation in the wizard).
- **Auth pass-through:** `authorization`, `x-api-key`, `anthropic-*`, `openai-*` headers forwarded verbatim; parda never stores credentials. Hop-by-hop headers dropped; `content-length` recomputed; upstream request sets `accept-encoding: identity` so responses can be rewritten.
- **Request redaction (JSON walk):**
  - Anthropic: `system` (string or text blocks), `messages[].content` (string | blocks: `text`, `tool_result.content` (string|blocks), `tool_use.input` (all string leaves), `document` text sources); images/documents with base64 → unscanned event.
  - OpenAI chat: `messages[].content` (string | parts `text`), `tool_calls[].function.arguments` (JSON string → parse → redact string leaves → re-serialize), `tool` role content; `image_url` → unscanned event.
  - OpenAI responses: `instructions`, `input` (string | items with `content` parts `input_text`/`output_text`, `function_call.arguments`, `function_call_output.output`).
  - All string leaves of the walked fields are redacted; keys and non-text fields untouched.
- **Response restoration:**
  - Non-streaming JSON: walk the same text-bearing fields (assistant `content[].text`, `tool_use.input`, `choices[].message.content`, `tool_calls[].function.arguments`, responses `output[]`) and restore.
  - Streaming SSE: parse events; per (content block / choice / output item) maintain a `StreamRestorer`; rewrite `text_delta.text`, `input_json_delta.partial_json`, `choices[].delta.content`, `delta.tool_calls[].function.arguments`, `response.output_text.delta`, `response.function_call_arguments.delta`; on block/choice end or `[DONE]`, flush held-back text into a synthetic delta event of the same type before the stop event. Unknown events pass through unchanged.
- **Guards:** reject requests whose `Host` is not loopback/`localhost` (DNS-rebinding) and any request carrying an `Origin` header unless allow-listed (browser CSRF), 403 with JSON error. No CORS headers emitted.
- **Errors:** upstream errors passed through (bodies restored). parda's own errors use provider-shaped JSON (`{"type":"error","error":{"type":"parda_…","message":…}}` for Anthropic; `{"error":{…}}` for OpenAI) with 4xx/5xx codes.
- **Events:** per request: provider, model, counts per kind, ML ms, total added ms, unscanned media, errors — never raw values unless `privacy.log_values=true`.

## 7. Clipboard

- **Watcher:** polls clipboard text every `clipboard.poll_ms` (300). On change (blake3 differs and not self-written): scan in background → cache `{hash → redacted, detections}`; emit `ClipboardScanned{counts}`.
- **Paste-safe** (hotkey default `Cmd+Alt+V` on macOS, `Ctrl+Alt+V` elsewhere; also `parda paste-safe` via IPC): read clipboard → redacted (cache or compute) → write redacted → synthesize paste (`Cmd+V`/`Ctrl+V` via `enigo`) → after 400 ms restore the original clipboard. If nothing to redact, paste original.
- **Restore-on-copy** (default on): when newly copied text contains surrogates from the vault → replace clipboard with restored text; emit `ClipboardRestored`.
- **Hotkey:** `global-hotkey` crate on a dedicated main-thread event loop (macOS requires main thread). Wayland: global hotkey unsupported → doctor explains binding a DE shortcut to `parda paste-safe`.
- **Permissions:** macOS Accessibility needed for synthetic paste; `parda doctor` checks and explains. If paste synthesis fails, parda leaves the redacted text on the clipboard and notifies via event ("press paste manually").

## 8. Daemon, IPC, service

- `parda daemon` runs in foreground (used by service managers). Tokio multi-thread runtime; clipboard + hotkey on the main thread loop; engine shared via `Arc`.
- **IPC:** `interprocess` local socket: Unix `<runtime_dir>/parda.sock` (dir 0700), Windows named pipe `parda-<username>`. Framing: newline-delimited JSON. Requests: `Status`, `Redact{text,scope}`, `Restore{text,scope}`, `Scan{text}`, `PasteSafe`, `Subscribe` (event stream), `RulesList/RulesAdd/RulesRemove`, `AllowAdd/AllowRemove`, `VaultStats`, `VaultWipe{scope?}`, `ConfigGet`, `ConfigSet{key,value}`, `Reload`, `Shutdown`. Responses `Ok{…}`/`Err{code,message}`. Protocol version handshake.
- **CLI fallback:** if the daemon is not reachable, `redact/restore/scan` run the engine in-process (same vault file; SQLite handles concurrency) and print a hint.
- **Service:** `parda service install|uninstall|status`: macOS LaunchAgent plist (`~/Library/LaunchAgents/dev.parda.daemon.plist`, RunAtLoad, KeepAlive); Linux systemd user unit (`~/.config/systemd/user/parda.service`); Windows Task Scheduler logon task (`schtasks`) running `parda daemon` hidden.
- **Paths** (`directories` crate, overridable by `PARDA_HOME` → everything under it): config `config.toml`, `rules.toml`; data `vault.db`, `models/`; logs `parda.log` (rotating, no raw values).

## 9. TUI (`parda tui`)

Tabs (keys `1`–`6`, `q` quit, `?` help):
1. **Dashboard** — daemon/proxy/clipboard status, model + execution provider, counts by kind (session/total), latency p50/p95, last errors.
2. **Live** — scrolling event feed (time, surface, kinds, ms); values masked (`R••• K•••`), `v` toggles reveal (only if `log_values` or local reveal permitted for recent in-memory events).
3. **Inspector** — input box; shows redacted output with highlighted spans and per-span kind/score/source; `r` toggles restore preview.
4. **Rules** — person blocks, terms, allow-list; add/edit/delete; saves `rules.toml` and triggers `Reload`.
5. **Vault** — counts per scope/kind, oldest/newest, wipe scope/all (with confirm).
6. **Setup** — proxy URL + env snippets for Claude Code/Codex/OpenAI SDK, clipboard toggles & hotkey, mode strict/fast, replacement style, model selection, doctor results.

## 11. Error handling & security summary

| Situation | Behaviour |
|---|---|
| ML error/timeout | strict: refuse (503 `parda_ml_unavailable`); fast: rules-only + event |
| Daemon down | agents get connection refused (fail-closed); CLI falls back to in-process |
| Vault key missing/corrupt | daemon refuses to start; doctor suggests `parda vault reset` (destroys mappings, confirms) |
| Upstream error | passed through, restored |
| Non-loopback Host / Origin present | 403 |
| Logs | counts/kinds/timings only; raw values only with `privacy.log_values=true` |
| Files | config/data dirs 0700, key file 0600, socket dir 0700 |

## 13. Testing

- **Unit:** validators (Luhn, Verhoeff, IBAN, GSTIN), each recognizer (positive + hard-negative fixtures), person-block expansion, merge rules, surrogate validity (generated Aadhaar passes Verhoeff, cards pass Luhn, PAN matches pattern…), determinism, case preservation, vault encrypt/decrypt/TTL, restorer.
- **Property tests (`proptest`):** `restore(redact(x)) == x`; stream restore invariant under arbitrary chunking.
- **Golden corpus** `bench/golden/*.jsonl` (hand-written, synthetic, Indian + global, chat-style + code/log-style, hard negatives); used by tests (rules tiers) and the eval harness (with model).
- **Proxy integration:** mock upstream (axum) for Anthropic + OpenAI chat + responses; non-stream and SSE; tool calls; verifies upstream never receives real values and client receives real values; guards (Origin/Host).
- **IPC integration:** daemon in-process on temp socket; client round-trips.
- **Bench:** `parda-bench eval` (precision/recall/zero-leak per kind) and `parda-bench latency` (p50/p95 per tier, per fragment size); results written to `bench/results/`.

## 15. Decisions log (made by implementer under delegation)

| Decision | Choice | Why |
|---|---|---|
| Default replacement | Realistic surrogates | Avoids "model fixes placeholder by hallucinating" failure; better fluency |
| Address/Org surrogate | Typed token in v0.1 | Realistic address synthesis is non-trivial; defer |
| Default mode | strict (fail-closed) | Privacy tool; names are the core promise |
| Dates | off by default | High false-positive rate; DOB only with context |
| Proxy port | 8787 | Unused by common dev tools |
| Clipboard restore-on-copy | on | Chat users otherwise see fake names in answers |
| IPC | local socket, NDJSON | Simple, debuggable, cross-platform |
| Vault | SQLite + app-level AEAD | Portable, no SQLCipher build pain |
| License | Apache-2.0 OR MIT | Rust ecosystem norm, permissive |
| Model | chosen by benchmark gate | Measure, don't guess |
