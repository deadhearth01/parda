# parda v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship parda v0.1 — a local daemon that redacts PII (rules + dictionaries + one ONNX model) from AI-agent API traffic and clipboard pastes, restores real values in answers (incl. streams and tool calls), managed by a CLI + ratatui TUI, packaged for one-command install on macOS/Windows/Linux.

**Architecture:** Cargo workspace of focused crates. `parda-engine` orchestrates detection tiers (`parda-detect`, `parda-ml`) and the encrypted surrogate vault (`parda-vault`). The `parda daemon` process hosts the engine, the axum proxy (`parda-proxy`), the clipboard service (`parda-clip`) and an IPC server (`parda-ipc`); `parda` CLI and `parda tui` are thin IPC clients (CLI falls back to in-process engine).

**Tech Stack:** Rust 1.99 (edition 2024), tokio, axum 0.8, reqwest, ort =2.0.0-rc.9 + tokenizers 0.21 (pinned by gline-rs 1.1), gline-rs, rusqlite (bundled), chacha20poly1305, hmac/sha2/hkdf, blake3, aho-corasick, regex, keyring, interprocess, arboard, global-hotkey, enigo, ratatui + crossterm, clap, serde/serde_json/toml, directories, proptest, dist (cargo-dist).

**Spec:** `docs/superpowers/specs/2026-10-11-parda-v0.1-design.md`

## Global Constraints

- All builds/caches/temp on the SSD: run `source scripts/dev-env.sh` before any cargo command; never write build artefacts to the boot disk.
- Local only, no telemetry; proxy binds `127.0.0.1:8787` by default.
- `ort = "=2.0.0-rc.9"`, `tokenizers = "0.21"` workspace-wide (gline-rs pin; ONNX Runtime `links` key forbids two versions).
- License `Apache-2.0 OR MIT`; never bundle non-commercial (CC BY-NC) or AGPL code/models.
- Logs and events never contain raw PII values unless `privacy.log_values = true`.
- Default mode `strict`: ML failure/timeout ⇒ refuse (proxy 503 `parda_ml_unavailable`), never silently send unredacted names.
- Byte offsets (`usize`) into UTF-8 strings everywhere; every slice boundary must be a char boundary.
- Anthropic `thinking` / `redacted_thinking` blocks are never modified in either direction (signatures).
- Keep compile parallelism ≤ 4 jobs (`CARGO_BUILD_JOBS=4`) — swap on the boot disk.
- Commit after every task; never push.

## Review Focus

1. **Non-ASCII text (Devanagari, emoji, accented names)** — redaction and streaming restore must never split a UTF-8 char; tests in Task 6 (stream chunks split inside multibyte chars) and Task 2 (recognizers next to Devanagari).
2. **Model echoes surrogates in a different shape** (`ARJUN MEHTA`, `Arjun's`, first name only) — restore must still map back; tests in Task 6.
3. **Very large agent requests** (100k+ token histories, ~1 MB JSON) — rules tier + cache must keep added latency low; perf test in Task 6 (1 MB redact < 300 ms debug-independent bound measured in release bench, unit test asserts < 2 s in debug) and cache-hit test.
4. **Unknown / signed content blocks** (`thinking`, `redacted_thinking`, server-tool blocks, new block types) — must pass through byte-identical and never crash the walker; tests in Task 9 and Task 10.
5. **Streaming must stay streaming** — proxy must forward SSE events incrementally (first client byte before upstream finishes) and handle upstream gzip/brotli by forcing identity; tests in Task 10.
