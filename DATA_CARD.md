# Data card — parda synthetic PII training data

Used to fine-tune the `parda-pii-edge` GLiNER model. Generated by `training/datagen`
(Python standard library only); nothing in it comes from real people or scraped text.

## How to reproduce

```bash
cd training
python -m datagen.generate --n 20000 --seed 7 --split train --out data/train.jsonl
python -m datagen.generate --n 2000  --seed 7 --split dev   --out data/dev.jsonl
python -m datagen.generate --n 2000  --seed 7 --split test  --out data/test.jsonl
```

Each run writes GLiNER-format `*.jsonl` (`tokenized_text` + inclusive word spans) and a
`*.chars.jsonl` sidecar with character offsets, `region` and `style`. Generation is
deterministic and prefix-stable (the first *k* examples of any run are identical).

## Sources and licences

- **Names**: hand-curated lists in `training/datagen/data/` — 1,200+ Indian first names
  (North, South, East, West, North-East; Hindu, Muslim, Sikh, Christian, Parsi, Jain,
  Buddhist), 400+ Indian surnames, ~390 global first names and ~335 surnames (Anglo,
  Irish, Hispanic, Portuguese, French, German, Slavic, Turkish, Arabic, Persian, Chinese,
  Japanese, Korean, Vietnamese, Yoruba/Igbo, Swahili …), with diacritics and apostrophes.
  Lists of common names are facts, not creative works.
- **Identifiers**: random and checksum-valid — Aadhaar (Verhoeff, first digit 2–9), PAN,
  GSTIN (mod-36), cards (Luhn), IBAN (mod-97, 8+ countries), IFSC, UPI handles, Indian and
  international phone formats, IPv4/IPv6, passports.
- **Vocabularies**: organisations, brands, cities, localities, landmarks — `data/*.txt`.
- All generated data and code: Apache-2.0 OR MIT (same as parda).

## Held-out evaluation

- The **test** split draws person names from a disjoint held-out partition (~15% of names
  that share no word with templates or other vocabularies); tests assert no held-out name
  ever appears in train or dev text.
- `bench/golden/names.jsonl` is a separate **hand-written** set (120 sentences: 60 India,
  40 global, 20 negatives) never produced by these templates.

## Design choices

- Person spans exclude honorifics and forms of address (`Dr.`, `Shri`, `Smt.`, `Mr.`, `ji`,
  `bhai`, `didi`, `bhaiya`, `anna`, `akka`, `sir`, `madam`) so redaction keeps the
  politeness markers and the model learns where a name ends.
- Hard negatives teach what is *not* personal data: brands and car models, festivals,
  cities on their own, version numbers, order and ticket IDs, amounts, generic roles.
- Public-figure names are **not** used as negatives (redacting a public name is a safe
  failure; missing a private one is not).

## Known gaps

- Text is English and romanised Hindi/Hinglish; no Devanagari, Tamil, Bengali or other
  native scripts yet.
- Templates are short (median ≈ 20 words); long documents are represented only by
  multi-sentence negatives.
- Synthetic distributions differ from real chats; evaluate on your own data before relying
  on the model for compliance.
