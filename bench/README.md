# Benchmarks

`parda-bench` measures what parda actually sends: it runs the full engine (dictionary, rules,
model, merge, policy, surrogates, restore) over a hand-written golden corpus.

```bash
cargo build --release -p parda-bench
target/release/parda-bench eval --model parda-pii-edge          # or gliner-pii-edge, none
target/release/parda-bench latency --model parda-pii-edge
target/release/parda-bench mock-upstream --port 9901            # fake LLM API for end-to-end tests
```

Models are read from `$PARDA_HOME/data/models` (or `--models DIR`). Reports are written to
`bench/results/` (git-ignored) and include every missed and leaked value.

## Golden corpus (`bench/golden/`)

| File | Cases | Contents |
|---|---|---|
| `names.jsonl` | 120 | 60 Indian and 40 global sentences with people and addresses (chat prompts, Hinglish, letters, tickets), 20 negatives |
| `rules.jsonl` | 81 | Structured identifiers: e-mail, phones (+91, US, UK), Aadhaar, PAN, GSTIN, UPI, IFSC, Voter ID, vehicle numbers, IBAN, cards, IP/MAC, URLs with tokens, SSN, NINO, API keys, JWTs, PEM keys — including inside Devanagari text |
| `negatives.jsonl` | 43 | Look-alikes that must not be redacted (versions, order IDs, ISBNs, UUIDs, dates without DOB context …) |

All values are invented. The corpus is written by hand and never generated by the training
templates in `training/datagen`, so it measures generalisation rather than template recall.

Metrics:
- **recall / precision per kind** — a prediction matches a gold span of the same kind when it
  covers it or overlaps at least half of the union;
- **zero-leak rate** — share of cases whose redacted text contains none of their gold values;
- **round-trip rate** — share of cases where `restore(redact(x)) == x`.

## Results — Apple M4, CPU, threshold 0.4

| Model | Person recall IN / GL | Person precision | Address R / P | Zero-leak | Round-trip | Mean per case |
|---|---|---|---|---|---|---|
| none (rules + dictionary only) | 0 / 0 | — | — | 0.502 | 1.000 | < 0.1 ms |
| gliner-pii-edge (INT8) | 0.970 / 0.955 | 0.922 | 0.75 / 0.27 | 0.995 | 1.000 | 2.3 ms |
| **parda-pii-edge** (fp32) | **1.000 / 1.000** | **1.000** | **1.00 / 1.00** | **1.000** | 1.000 | 9.4 ms |

Every structured identifier kind (Aadhaar, PAN, GSTIN, UPI, IFSC, cards, IBAN, phones, e-mail,
secrets …) has recall and precision 1.0 in all three rows: the rule tier validates checksums and
shapes, the model is only needed for names and addresses.

## Latency — Apple M4, CPU

| Step | p50 | p95 |
|---|---|---|
| Rule scan, 64 words | 0.01 ms | 0.01 ms |
| Rule scan, 256 words | 0.02 ms | 0.03 ms |
| Rules redact, 984 KB request, uncached | 15.2 ms | 15.2 ms |
| gliner-pii-edge, 64 / 256 words | 8.9 / 36.9 ms | 9.3 / 41.6 ms |
| parda-pii-edge, 64 / 256 words | 43.4 / 159.7 ms | 47.1 / 187.2 ms |

Model numbers were taken while other builds were running; an idle machine is faster. Text seen
before (agents resend the whole history each turn) is served from the cache and skips the model.

See [MODEL_CARD.md](../MODEL_CARD.md) for how `parda-pii-edge` was trained and why it ships in
fp32.
